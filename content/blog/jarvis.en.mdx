This project did not start as a voice assistant. It started as a question.

TypeSafe released Jev, which they call a "System One" model. It is a strange kind of model. It does not write anything. You give it some text and a few multiple-choice questions, and it answers each one with a probability for every option and a confidence score. It takes about a tenth of a second.

So I wanted to understand where something like that fits. <strong className="text-secondary">When would I use Jev instead of an LLM?</strong> Not in theory. In something I would really use.

So I started to experiment, and I needed a real use case to test it on.

## The idea: talk to my Mac

Choosing between options is exactly what you need to understand a command. "Volume up", "turn it up" and "it's too loud" are different sentences, but they all point to the same action. Jev does not have to write a single word to get that right. It only has to pick.

So the idea came to me: run voice commands on my Mac.

There are tools that already do this, but I wanted to go further and see how far a model like Jev could take it. And I already had half of it. I use superwhisper every day to dictate. So I only needed a hook. When I say a keyword at the start of a sentence, the text goes to Jev with a list of things it could mean, and a script does the rest.

I picked the things I do every day:

- **Obsidian**, which I use for notes. "Create a note called Shopping list saying milk and eggs."
- **Search in the browser** without typing. "Go to github dot com."
- **Take a picture.** "Take a selfie."
- **Open an email** with a subject and a body already written. "Write an email to Maya about Friday."

The keyword was "Jev" at first, after the model. But the speech model heard "Jeff" every single time. I tried "Jarvis", and it was spelled right in all 6 tests. That is how it got its name.

## Where Jev hit its limit

The first three worked well. Jev picked the right action, a small piece of code pulled out the note text or the website, and a script did the work.

The email was trickier, and it showed me exactly where Jev ends.

Jev can tell that "write an email to Maya about Friday" is an email. It can even pick between options I prepare for it. But it cannot write the email. It cannot turn "about Friday" into a subject and a body, and it cannot turn "tomorrow at 9" into a real date. <strong className="text-secondary">Jev is very good at choosing, and it cannot write.</strong>

That was the answer to my question, and it changed the goal. Jev would not replace an LLM. It would sit in front of one.

## The approach: each part does what it is best at

So the goal became broader. Instead of one model doing everything, every command goes down the same path, and each step only runs if the one before it could not answer.

**1. Patterns first.** Most of what I say to a computer is boring. "Volume up." "Pause the music." "Open my downloads." Those are exact shapes, so plain patterns catch them. There are 49 of them now. A match takes less than a millisecond and needs no model at all.

**2. Jev when the patterns cannot answer.** "Make it darker in here" matches no pattern. Jev picks dark mode with 0.95 confidence, in 123 ms. It answers two questions in one call: which app is this for, and which action inside it. One option is always "unknown", for questions and small talk, so "did you take the picture?" does nothing.

**3. An LLM only for what Jev cannot do.** Writing an email draft. Turning "Friday at 3" into a date. Finding the address behind a name. And choosing an action if Jev is ever unsure. It never writes code that runs, and it never sends anything.

**4. Scripts do the work.** Every action is a script written ahead of time. The models decide and write. Only scripts I have read can touch my computer.

The email flow shows all of it. A pattern or Jev recognises the request. The LLM writes the draft. A script opens it in Gmail with the recipient, subject and body filled in. I can ask for changes out loud. But it never sends. Even if I say "send it", it only tells me the draft is ready. Sending is my click.

## Almost no cost

This was important for me. I did not want an experiment that sends every sentence to a paid API.

- **Patterns and scripts** are free and run on the Mac.
- **Jev** is one quick API call, only when a pattern cannot answer.
- **The LLM** is GPT-5.6 Luna, and it runs on my ChatGPT Plus plan through the same sign in that Codex uses. So it counts against the plan I already pay for, not against a bill. It goes through LiteLLM, so any other model, or a local one, works too.
- **The tools** around it are free and open source.

## From script to tool

The first version was one Python script for a demo. Then I kept improving it, and it became a real command line tool, `jarvis`:

- **It listens** through superwhisper, through any voice tool that copies its text, through the Mac's own microphone, or through the keyboard.
- **`jarvis doctor`** checks everything it needs: the voice input, the Jev key, the LLM sign in, the apps, the Obsidian vault, and the macOS permissions. Each problem comes with the exact fix.
- **Every app is a small file** with a description, some example phrases, the patterns and the script. Jev's options come straight from those files, so a new app is a new option, with no code changes.
- **`jarvis add`** teaches it a new app by asking a few questions: which app, what you call it, which actions you want. It can also ask the LLM to suggest actions from the app's own scripting dictionary, and it shows me every script before saving it.
- **`jarvis setup`** is a short questionnaire for the rest: which voice tool, the name it answers to, the browser, the vault, the keys. The first time you run `jarvis`, it offers to run it for you.
- **Email recipients** come from the Contacts app and, if you connect it, your Gmail contacts, allowing for the way speech-to-text spells names.

Right now it knows 11 apps and 25 actions: apps in general, the browser, Music, system settings like volume and dark mode, Finder, Reminders, Calendar, email, Obsidian, Photo Booth, and your own Apple Shortcuts.

## The results

I measured 69 commands: every Jarvis command I had dictated through superwhisper, plus every phrase I had used to test Jev. They ran through the real decision path with live model calls, in a dry run, so nothing was executed.

So, back to the original question. **Where does Jev fill the gap?**

- **Natural phrasing.** "Put on some tunes", "it's too loud", "capture my face". No pattern knows them. Jev got all of them right.
- **Telling questions from requests.** All 8 questions and comments came back as "unknown" with 0.96 confidence or more, so nothing ran.
- **Speed.** I speak for about 5 seconds, and superwhisper needs about 200 ms to write it down. Jev adds about 116 ms. That is around 2% of the whole command.

And where it does not: **writing.** The LLM ran 6 times, always to fill in a detail, like a recipient or a date. It took between 1 and 5 seconds, so it is the slowest step by far, and the reason it only runs when something required is missing.

## What went wrong along the way

**The second selfie.** I said "Jarvis, did you take the picture?", and it took another selfie. The word *picture* was enough for the simple rules. Jev fixed it, but only after two changes. I had described "unknown" as just "anything else", which tells a model very little. And my own code ignored a confident "unknown" and fell back to the rules anyway. <strong className="text-secondary">A confident "I don't know what you want" is an answer. Treat it like one.</strong>

**Speech is the weakest link.** Superwhisper wrote "github.com" as "OpenGeekHove.com", "Obsidian" as "of CDN", and one contact's name as a completely different name, three times. No model can fix a word that was never said. The fix lives in the speech tool's vocabulary list, not in a prompt.

**The boring bugs took the longest.** Photo Booth's "Take Photo" no longer has a keyboard shortcut. Contacts refused to open from a script. The ChatGPT plan only answers when the response is streamed. None of these were AI problems.

## Limits and permissions

It is still an experiment, and it has real limits.

**It only knows the apps it has skills for.** Apps with a scripting dictionary, like Music or Mail, are easy. Apps without one need clicks and shortcuts, which break more easily. And some scripts have gaps: the calendar one often misses repeating events.

**It needs your permission for everything it touches.** macOS asks before a terminal can type into other apps, use the microphone, or control Contacts, Calendar or Reminders. That is how it should be. `jarvis doctor` tells you which permissions are missing and where to turn them on.

**Until now, only one person has used it,** and that is me. The 69 commands were measured as a dry run. Some actions I have used for real, like the selfie, the notes and the email drafts. Others were only checked in dry runs and by compiling their scripts.

## Try it yourself

Jarvis is open source, under the MIT license: <a href="https://github.com/craigraphics/jarvis" target="_blank" rel="noopener noreferrer">github.com/craigraphics/jarvis</a>.

```sh
uv tool install git+https://github.com/craigraphics/jarvis
jarvis setup
jarvis doctor
jarvis
```

You need a Mac, Python 3.11 or newer, and <a href="https://docs.astral.sh/uv/" target="_blank" rel="noopener noreferrer">uv</a>. With nothing else, the exact commands already work: "volume up", "open Notes", "take a selfie". A Jev key from TypeSafe adds natural phrasing and ignores questions. An LLM adds email drafts and details like dates, and it can be your ChatGPT plan, an API key, or a model running on your Mac.

If something breaks, please open an issue. That is exactly the feedback this experiment needs.

## What comes next

The goal is simple: more voice commands that do more things on your Mac, at almost no cost.

That means two things. Making new apps easier to add, so the questionnaire in `jarvis add` is enough for most of them. And looking for more places where a fast, honest "pick one of these" model is the right tool, instead of a big model that writes.

## FAQ

**Do you really need Jev?**
For a short scripted demo, patterns are enough. Jev matters when people speak naturally, when there are many apps, and when a question should do nothing.

**Does Jarvis send emails?**
No. It writes the draft and opens it. Sending is always your click.

**What does it cost to run?**
Patterns and scripts are free. Jev is one quick call when a pattern cannot answer. The LLM runs on my ChatGPT Plus plan, so there is no extra bill.

**Which voice tools does it work with?**
Superwhisper, any tool that copies its text to the clipboard, the Mac's own microphone with local whisper, or plain typing.

**Does it work offline?**
The patterns and the scripts do. Jev and the LLM need the network.

**Can I try it?**
Yes. It is on GitHub under the MIT license, and the install is one line (see "Try it yourself" above).

**How do you teach it a new app?**
`jarvis add <app>` asks a few questions and creates the skill file. With `--ai`, the LLM suggests actions for that app, and you approve each one.

## What I learned

I started by asking where Jev fits instead of an LLM. The answer I found is that it does not replace one. It goes in front of one.

A pattern is the right tool more than half the time. A small model that can only choose is the right tool for most of the rest, and it is honest when it does not know. The LLM is great at writing, and it should only write.

Where else do you think a model that only chooses would beat one that writes?
